Command-based

Command-based code declares what should happen

Checking the button every loop

if (condition.get()) {

  if (!pressed) {

    piston.set(

        DoubleSolenoid.Value.kForward);

    pressed = true;

  }

} else {

  pressed = false;

}

Declaring it once

new Trigger(condition::get)

    .onTrue(Commands.runOnce(

        () -> piston.set(

            DoubleSolenoid.Value.kForward)));

WPILib docs: What Is “Command-Based” Programming?

5

Both sides come from WPILib’s docs, with longer lines wrapped, and both do the same thing: fire a piston when a condition becomes true. On the left, the code checks the condition every loop and tracks whether it has already acted. On the right, the connection is declared once at startup. WPILib calls this declarative programming: the library does the work of checking the button and scheduling the command.
