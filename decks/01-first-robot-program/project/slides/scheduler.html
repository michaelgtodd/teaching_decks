Control theory

The scheduler reads, decides and acts every 20 ms

The four steps are WPILib’s Scheduler Run Sequence. Step 2 reads the buttons and starts bound commands. Step 3 runs every scheduled command.

Step 1: subsystems

each periodic() runs

Step 2: poll triggers

read the buttons, start bound commands

Step 3: run commands

each execute(), then isFinished()

Step 4: default commands

schedule them for idle subsystems

CommandScheduler.getInstance().run()

called from robotPeriodic() in Robot.java, every 20 ms

WPILib docs: The Command Scheduler

6

A control system repeats one loop: read inputs, decide, act. In a command-based program, that loop is CommandScheduler.run, which TimedRobot calls from robotPeriodic every 20 milliseconds. WPILib says this call is required: without it, the command framework does not run. The template already includes it, so nothing needs adding. A command bound to a button runs its initialize method inside step 2, when its trigger is polled. The command in this deck sets the motor at that point.
