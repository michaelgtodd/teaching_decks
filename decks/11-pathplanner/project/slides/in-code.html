/** First Auto, written in Java: the same two paths and the same launch. */

public static Command firstAutoInCode(Launcher launcher) {

  try {

    PathPlannerPath toHub = PathPlannerPath.fromPathFile("Drive to Hub");

    PathPlannerPath backOff = PathPlannerPath.fromPathFile("Back Off");

    return Commands.sequence(

        AutoBuilder.resetOdom(toHub.getStartingDifferentialPose()),

        AutoBuilder.followPath(toHub), // its spinUp marker still fires

        launcher.launch(),

        AutoBuilder.followPath(backOff));

  } catch (Exception e) {

    DriverStation.reportError("Path file: " + e.getMessage(), false);

    return Commands.none();

  }

}

This is the fourth way: load paths by file name and compose them with Deck 2’s tools. It builds the same routine as First Auto. resetOdom does what the Reset Odometry box does, and mirrors the pose for red. followPath still fires the spinUp marker, as long as spinUp was registered before the path file loads. Use this when a routine needs logic the app cannot draw, such as choosing a path from a sensor. Otherwise the app is easier to read and change.
