Register names, then build the chooser

RobotContainer.java

// 1. Tell PathPlannerLib how to drive this robot.

boolean ready = PathPlannerSetup.configure(drive);

 

// 2. Register every name used in the app, before any auto is built.

NamedCommands.registerCommand("spinUp", launcher.spinUp());

NamedCommands.registerCommand("launch", launcher.launch());

 

// 3. One chooser entry per .auto file in deploy/pathplanner/autos, plus "None".

autoChooser = ready ? AutoBuilder.buildAutoChooser() : new SendableChooser<>();

if (!ready) {

  autoChooser.setDefaultOption("None", Commands.none());

}

SmartDashboard.putData("Auto Chooser", autoChooser);

getAutonomousCommand() returns autoChooser.getSelected().

Order matters. buildAutoChooser loads every auto file at that moment, and each named command is looked up as the auto is built. So every registerCommand call must come before it. The chooser has one entry per auto file, plus None as the default, and appears on the dashboard as Auto Chooser, in Elastic from Deck 5 for example. Loading every auto at startup also avoids a delay when autonomous begins, which the PathPlanner docs recommend.
