Best practice

Treat path and command names as code

Pick clear names once. Rename only in the app, then fix the Java in the same commit.

The code loads paths by file name and commands by name. A rename on one side breaks the other without a build error.

Deck 11 · PathPlanner

27

Renaming a path renames its file, and an auto in the app follows along, but Java that loads Drive to Hub by name does not. Renaming a command in Manage Events updates the app, not your registerCommand calls. Neither mistake stops the build. Commit the deploy/pathplanner folder with the code that uses it, so a teammate who checks out the project gets both halves together.
