Common mistake

The auto drives, but never launches

What you see

Drive to Hub and Back Off run, the launcher never moves, and the Driver Station shows a PathPlanner warning.

Why it happens

registerCommand ran after buildAutoChooser(), or the spelling differs from the app.

The fix

Register every name first, spelled exactly as in Manage Events.

PathPlanner attempted to create a command 'launch' that has not

been registered with NamedCommands.registerCommand

When PathPlannerLib builds an auto and meets a name nobody registered, it prints this warning and puts in a command that does nothing, so the rest of the auto still runs. That makes the mistake easy to miss: the robot drives correctly and only the mechanism stays still. Names are case sensitive, so launch and Launch are different. Read the Driver Station messages after every deploy. The warning text is from NamedCommands.java in PathPlannerLib 2026.1.2.
