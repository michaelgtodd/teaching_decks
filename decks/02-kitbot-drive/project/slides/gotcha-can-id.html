Common mistake

A CAN ID that does not match

What you see

The log shows [Spark Max] IDs: 6, Unable to retrieve SPARK firmware version and timed out while waiting. That motor stays still.

Why it happens

No SPARK answers at the ID in Constants. Every new SPARK ships as ID 0, and each needs its own number.

The fix

Set IDs in REV Hardware Client 2 over USB, robot off, one SPARK at a time. Then match Constants.

Those lines are real, from a team’s log in March 2026. They had new SPARKs and had not set the IDs. The full message tells you the fix: “Please verify the deviceID field matches the configured CAN ID of the controller, and that the controller is connected to the CAN Bus.” Two related problems. If two IDs are swapped there is no error, and the wrong wheel just moves. And a SPARK that has been on the roboRIO’s CAN bus will not run a motor over USB: disconnect CAN and power-cycle it first.
