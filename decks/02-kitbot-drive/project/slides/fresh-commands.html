Best practice

Build a new command for each use

Call the factory again each time. One command object can go in only one group.

Reusing one makes WPILib throw: Commands that have been composed may not be added to another composition or scheduled individually!

// Wrong: one command object in two groups

Command fwd = drive.driveArcade(() -> 0.4, () -> 0.0).withTimeout(2.0);

Command autoA = Commands.sequence(fwd, Commands.print("A"));

Command autoB = Commands.sequence(fwd, Commands.print("B")); // throws

// Right: each call to the method makes a new command

Command autoC = DriveAutos.leaveAndTurn(drive);

When a command is put in a group, the scheduler marks it as composed. Putting the same object in a second group, or scheduling it alone, throws the error on the slide when the robot code starts. Factory methods avoid this, because each call returns a new command. That is one more reason the habits slide prefers factories.
