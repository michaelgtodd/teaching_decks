1

Reset

Starts from a known state, so a swapped-in spare behaves.

2

Persist

Saves to the SPARK, so settings survive a brownout or breaker trip.

3

Once, at startup

Saving takes time and blocks the SPARK. Never do it in a loop.

(1 min) Building a config changes nothing on the robot. configure sends it to the SPARK. Reset matters at competition: if you swap in a spare with unknown settings, your code still sets it up correctly. Persist matters because a breaker trip or brownout can restart a SPARK mid-match, and without it the SPARK comes back without your settings. If a kid has seen other code: FIRST’s KitBot zip imports these two modes from SparkBase. In REVLib 2026.0.5 that location is marked for removal, so we import them from com.revrobotics.
