An autonomous routine is one command

DriveAutos.java

/** The same routine as a list: easier to read, reorder and extend. */

public static Command leaveAndTurn(CANDriveSubsystem drive) {

  return Commands.sequence(

          drive.driveArcade(() -> AUTO_SPEED, () -> 0.0).withTimeout(DRIVE_OUT_SECONDS),

          drive.driveArcade(() -> 0.0, () -> 0.0).withTimeout(PAUSE_SECONDS),

          drive.driveArcade(() -> 0.0, () -> AUTO_SPEED).withTimeout(TURN_SECONDS),

          Commands.print("Auto finished"))

      .withName("Leave and turn");

}

getAutonomousCommand() in RobotContainer returns this. Robot.java runs it when autonomous starts and cancels it when teleop starts.

Commands.sequence takes the steps as a list, which is easier to read and reorder than a chain of andThen calls. Every number comes from Constants, so tuning the routine means changing one line. The routine drives by time, so it is open loop: battery level and carpet change how far the robot goes. The template Robot.java already schedules whatever getAutonomousCommand returns in autonomousInit and cancels it in teleopInit. Deck 11 replaces the timed steps with paths that use encoders and a gyro.
