Best practice

Keep sim code out of the real robot’s path

Keep sim code in simulationPeriodic() and DriveSim. Drive the same commands in sim and on the robot.

Your commands never ask whether they are in a simulator, so what you test is what runs on the robot. Code that never runs on the roboRIO can’t break it at an event.

The commands didn’t change at all, and neither did RobotContainer. The physics lives in one class that’s only built in simulation. That matters for two reasons. What you test is what runs on the robot, so passing in sim means something. And code that never runs on the roboRIO can’t break it at an event. Avoid checks like ‘if simulation’ inside commands.
