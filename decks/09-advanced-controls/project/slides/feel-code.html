  private double shapedForward() {

    double x = -driver.getLeftY();

1   x = MathUtil.applyDeadband(x, DEADBAND);

2   x = MathUtil.copyDirectionPow(x, STICK_EXPONENT);

3   return forwardLimiter.calculate(x * DRIVE_SCALE);

  }

   

  private double shapedTurn() {

    double x = -driver.getRightX();

1   x = MathUtil.applyDeadband(x, DEADBAND);

2   x = MathUtil.copyDirectionPow(x, STICK_EXPONENT);

3   return x * TURN_SCALE;

  }

1

Deadband first

Throw away drift before anything else sees it.

2

Then the curve

copyDirectionPow keeps the sign, so reverse works.

3

Scale, then limit

Now 0.7 stays 0.7 at full stick, and the limiter sees the final value.

Deck 9 · Advanced controls

6

The steps run top to bottom. Flip the sign, drop the deadband, apply the curve, scale, and limit last so the limiter sees the final value. A plain power would lose the sign, because a negative number squared is positive, and the robot could not reverse. The limiter is a field, not a local variable, because it has to remember its last value. Call it once per loop, which a supplier does for you. Turning gets a curve but no limiter, like the example in the WPILib docs.
