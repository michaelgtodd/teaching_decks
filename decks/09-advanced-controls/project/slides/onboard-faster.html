(1.5 min) Picture steering a car while looking away and glancing back every few seconds. Every decision is late, so you over-correct. Now look at the road all the time. This is Deck 6’s arm at the same kP 50, with the loop running every millisecond instead of every 20. It still overshoots, but it settles in 0.42 seconds. REV’s docs say the onboard loop updates every 1 ms. The encoder plugs straight into the SPARK, so nothing waits on CAN, and your code only sends a new goal. This plot is our model, with no sensor filtering, so treat it as the idea and not a promise for your robot.
