Common mistake

One side of the drive runs away

What you see

You enable the speed loop, and one side slams to full speed. The robot spins or curves hard.

Why it happens

The sides are mirror images, so one encoder counts backward. Speeding up looks like slowing down, so P pushes harder.

The fix

Disabled, wheels up: turn each wheel forward by hand. Both speeds must rise. If one falls, flip it with setReverseDirection.

(1 min) Deck 6 showed this on an arm, and a drivetrain has a new way to get it, because the two sides face opposite ways. We tried it in the simulator: with the left encoder counting backward, the left side ran to full speed while the right side held the goal. Feedback only works if pushing forward makes the reading go up. So check both sides before the first closed-loop enable, every time an encoder is changed. Keep someone ready on Enter, and start with the wheels off the ground.
