# Deck 7 sources

Everything below was checked on **2026-11-04**. Vendor pages change often, so check again before reusing a claim.

## Compile check

`check-deck.sh 7` compiles `frc/robot/deck7/` against WPILib 2026.2.1, REVLib 2026.0.5 and Phoenix 26.3.0 with `-Xlint:deprecation -Xlint:removal`. Result: compiles, no warnings. This is the authority for every class, method, package and return type in the code slides.

## REV's online Javadoc documents 2027 alpha, not 2026

`codedocs.revrobotics.com/java/` was generated by javadoc 25 and shows `Signal<Boolean> isAtSetpoint()`, `SparkLowLevel.ControlType` and `rangeOffset()`. Those are REVLib 2027 alpha APIs, so that site was **not** used as a 2026 source.

- Confirmed by compile: `isAtSetpoint()` returns `boolean`; `ControlType` is `SparkBase.ControlType`; `feedForward.kV/kCos/kCosRatio`; `follow(leader, invert)`; `ClosedLoopSlot.kSlot3`; `AbsoluteEncoderConfig.Presets.REV_ThroughBoreEncoderV2`; `zeroOffset`.
- Confirmed by REV's 2026 docs instead: kG and kCos behavior, MAXMotion behavior, the 80 A default.
- Removed from the deck because only that site supported them: "follow copies voltage output" and "Smart Current Limit is brushless only".
- Still resting partly on that site, so treat as weaker: "SPARK has no battery-side current limit" (also supported by the absence of any such parameter in REV's [SPARK MAX parameter table](https://docs.revrobotics.com/brushless/spark-max/parameters)), and "following stays within a vendor" on the REV side (CTRE's side is from the 2026 `Follower` Javadoc, "follow the motor output of another Talon"). The trapezoid-only claim is backed by REV's [MAXMotion page](https://docs.revrobotics.com/revlib/spark/closed-loop/maxmotion-position-control) and the [REVLib changelog](https://docs.revrobotics.com/revlib/install/changelog).

## What the plot simulates

Computed in `deck.mjs` with a 0.1 ms step. A point-mass arm (2 kg, 0.5 m, so J = 0.5 kg·m²) on a 60:1 NEO 2.0 using [REV's spec table](https://docs.revrobotics.com/brushless/neo/2.0), with a 40 A clamp, a 12 V clamp, ideal kG feedforward and P control, no friction or backlash, moved from 45° to 55°.

- The 20 ms sensor age at 50 Hz is **an assumption**, not a measurement. With a 10 ms old reading at the same gain, overshoot is about 2.3° rather than 4°, and the conclusion holds.
- An earlier version used a 45° step and claimed lower gain was slower. The numbers did not support that clearly, because the 12 V limit dominates big moves. The deck now uses a small correction and states the big-move result in the notes.

## Inference, and things not confirmed

- **How REVLib 2026 behaves on firmware 27.0.0.** Partly answered: REVLib 2026.0.5 treats firmware year 27 as too new. `c_Spark_Create_Inplace` in `libREVLibDriver.so` returns `kFirmwareTooNew` for any year above 26 and sends the error text to the Driver Station. `SparkLowLevel.java` then carries on without throwing ("Don't throw for 2026 season"). Read from the library on 2026-11-04, not run against real firmware. REV does not say more. Anything about that pairing is our inference, and the deck labels it so. This includes the `Presets.REV_ThroughBoreEncoderV2` preset on 27.x: the release notes do not list it as affected, but we cannot see what it sets.
- **The wrong-sensor reboot bug on 26.1.5.** The 27.0.0 SPARK MAX notes list the fix for "closed loop sensor is not the main encoder and idle mode is brake", which matches `RevArm`. The 26.x notes do not mention it. That 26.1.5 has it is inferred, and no workaround is documented. The notes tell mentors to test a reboot.
- **Whether Hardware Client 2 offers 27.0.0 today.** The docs describe the most up-to-date default but do not name a version. We could not run the client.
- **Exact wording of the REVLib firmware warning.** Not published, so the deck paraphrases the changelog and does not quote it.
- **NEO 2.0 on Talon FXS.** Not in CTRE's list or enum. Teams report it works, in a [Chief Delphi thread](https://www.chiefdelphi.com/t/talon-fxs-compatability/523810), but its sensor cable pinout is unresolved there. The slide says "Not listed by CTRE".
- **Minion on a SPARK.** Neither vendor documents it. R505 does not forbid it. The slide says "Not documented".
- **NEO 2.0 on a Flex Dock.** REV says "all SPARK brushless motor controllers" and the dock supports REV brushless motors, but no page names this exact pairing.
- **SPARKs on a CANivore.** No REV or CTRE page says this outright. Inferred from REVLib 2026 constructors having no bus argument and from CTRE's docs describing the CANivore as controlling CTR Electronics devices.
- **Arm generation.** CTRE's changelog mentions generated Arm subsystems from `corvus`, a CLI tool. Tuner X's docs list only swerve and elevator, so the deck claims only those.
- **Prices.** None are quoted, on purpose.

## Simulation row (2026-11-04)

The REV side was measured: REVLib 2026.0.5's simulated SPARK reads the kCos angle as degrees, so an arm using kCos settles high in simulation (see `decks/06-arm-pid/SOURCES.md`). A public report covers related issues on 2027 alphas: [SystemcoreTesting #425](https://github.com/wpilibsuite/SystemcoreTesting/issues/425). The CTRE side was **not** run, so this row is not a head-to-head test of simulator accuracy.
