Arm move: profile and command

REVLib 2026

config.closedLoop.maxMotion

    .cruiseVelocity(CRUISE_RPM)

    .maxAcceleration(ACCEL_RPM_PER_S)

    .allowedProfileError(PROFILE_ERROR_ROT);

 

public Command moveTo(double degrees) {

  double rotations = degrees / 360.0;

  return runOnce(() -> {

    target = rotations;

    controller.setSetpoint(rotations,

      ControlType.kMAXMotionPositionControl);

  }).andThen(waitUntil(this::atTarget));

}

Phoenix 6 2026

var magic = config.MotionMagic;

magic.MotionMagicCruiseVelocity = CRUISE_RPS;

magic.MotionMagicAcceleration = ACCEL_RPS2;

 

public Command moveTo(double degrees) {

  double rotations = degrees / 360.0;

  return runOnce(() -> {

    target = rotations;

    motor.setControl(

        request.withPosition(rotations));

  }).andThen(waitUntil(this::atTarget));

}

Deck 7 · REV vs CTRE

13

Both commands look nearly the same. Convert degrees to rotations in Java, send one target, then wait until the arm arrives. Nothing loops on the roboRIO, unlike your Deck 6 subsystem. Velocity units differ: REV uses RPM, CTRE uses rotations per second. These are the same motion. Not on the slide: on REV, configure with PersistMode saves settings so they survive a brownout. On CTRE, apply saves them and resets anything you left out. This arm rests just above level, because the SPARK reading wraps at 0. We left out kS because firmware 27 changes how it acts at a zero velocity setpoint. Timing: 1 minute.
