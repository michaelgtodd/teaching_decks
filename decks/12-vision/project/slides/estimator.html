WPILib docs: Pose Estimators

11

This is Deck 10’s drivetrain with one change. DifferentialDriveOdometry becomes DifferentialDrivePoseEstimator, and periodic() still calls update() every loop with the gyro and both wheel distances. WPILib’s docs call the estimators drop-in replacements for odometry. If you never add a vision pose, it behaves like odometry. The new method is the door that camera code uses. Keeping it on the drivetrain means the Limelight and PhotonVision classes in this deck both feed the same estimator, and you can switch between them without touching the drivetrain.
