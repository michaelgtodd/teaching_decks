Common mistake

run means something different

What you see

A drive command copied from v2 moves for one loop, then stops. The command ends at once.

Why it happens

v2’s run calls its code every 20 ms. v3’s run calls its function once, and a function with no loop ends right away.

The fix

Use runRepeatedly where v2 used run, or write the loop yourself with coroutine.yield().

run(() -> drive.arcadeDrive(f, r))           // v2: every 20 ms

run(c -> drive.arcadeDrive(f, r))            // v3: once, then ends

runRepeatedly(() -> drive.arcadeDrive(f, r)) // v3: every 20 ms

This is the trap most likely to catch a team porting Deck 2. Both versions have a method called run, and both compile, but they mean different things. In v3, run starts a coroutine command: the function runs once, and only a loop with a yield makes it last. runRepeatedly is the direct match for v2’s run. Read every run call when porting code, rather than changing imports and hoping.
