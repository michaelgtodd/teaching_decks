DriveAutos.java

/** The builder: closest to Deck 2's Commands.sequence. */

public static Command leaveAndTurn(KitBotDrive drive) {

  return Command.sequence(

          drive.driveFor(AUTO_SPEED, 0.0, DRIVE_OUT),

          drive.idleFor(PAUSE),

          drive.driveFor(0.0, AUTO_SPEED, TURN))

      .named("Leave and Turn");

}

idleFor holds still because KitBotDrive makes its idle drive at zero. The name ends the builder.

Command.sequence works like v2’s Commands.sequence, except that it is a builder: it becomes a command only when it is named. driveFor is a small factory in KitBotDrive: runRepeatedly with a timeout. idleFor is built into every mechanism. By default it does nothing at all, which on a drivetrain would let motor safety cut the motors and print the same error as Deck 2’s waitSeconds mistake. So KitBotDrive overrides idle to drive at zero every loop.
