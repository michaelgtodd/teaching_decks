DriveAutos.java

/** The coroutine: plain Java, one step after another. */

public static Command leaveAndTurnSteps(KitBotDrive drive) {

  return Command.requiring(drive)

      .executing(coroutine -> {

        coroutine.await(drive.driveFor(AUTO_SPEED, 0.0, DRIVE_OUT));

        coroutine.await(drive.idleFor(PAUSE));

        coroutine.await(drive.driveFor(0.0, AUTO_SPEED, TURN));

        System.out.println("Auto finished");

      })

      .named("Leave and Turn (steps)");

}

await starts a command and waits for it to end. Any Java fits between steps.

Here the routine is ordinary code: each await starts a command and pauses this one until that command ends. Between steps you can write any Java, such as an if that skips a step when a sensor says so, or a print. requiring(drive) keeps the drive owned for the whole routine. With noRequirements instead, the drive would be free between steps, so its default command, the gamepad drive, could run for a moment. Child commands may share the parent’s requirements in v3 without interrupting it.
