Priorities replace “interruptible or not”

When a new command conflicts with a running oneWhat happens
The new one has a higher priorityIt starts. The old one is cancelled.
They have the same priorityIt starts. The old one is cancelled.
The new one has a lower priorityIt is discarded. The old one keeps running.

The default priority is 0. Command.LOWEST_PRIORITY suits default commands and idles.

WPILib docs: Migrating from Commands v2

9

In v2, a command was either always interruptible, the default, or never interruptible, with kCancelIncoming. v3 gives every command a whole number priority instead. Equal priority behaves like v2’s default: the newest command wins. A higher number protects a command from ordinary ones, which is useful for something like a homing routine that must finish. Commands inside a group inherit the group’s priority when it is higher than their own.
