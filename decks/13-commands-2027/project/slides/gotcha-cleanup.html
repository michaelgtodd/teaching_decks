Common mistake

The roller keeps spinning after a cancel

What you see

Bound with whileTrue, the feeder keeps running after the driver lets go of the button.

Why it happens

Cancelling stops the function where it is, inside waitUntil. The line that stops the motor never runs.

The fix

Put stop code in whenExited, which runs however the command ends, as on the first command slide.

motor.setThrottle(FEED_SPEED);

coroutine.waitUntil(this::hasPiece); // cancelled while waiting here

motor.setThrottle(0.0);              // so this never runs

In v2, end ran whether a command finished or was interrupted, so cleanup in end always happened. In v3, a cancelled command is never resumed: the scheduler drops it at its last yield. Code after that point is skipped. whenExited runs on every kind of ending, and whenCanceled only on cancellation. Keep both to a single quick action, such as setting a motor to zero.
