The big idea

Four methods in v2, one function in v3

Commands v2

initialize() runs once, at the start.

execute() is called by the scheduler every 20 ms.

isFinished() is checked every loop.

end(interrupted) runs once, at the end.

Commands v3

One function runs top to bottom, like normal Java.

coroutine.yield() pauses until the next 20 ms loop.

Reaching the end, or return, finishes the command.

whenExited(...) holds cleanup that runs however it ends.

In v2, the scheduler calls your methods, and you split one action across four of them. New programmers often write a while loop inside execute and freeze the robot, because execute is supposed to return quickly. In v3, a command is one function. A loop is a normal loop, and the yield inside it hands control back to the scheduler until the next 20 ms tick. That is the coroutine: a function that can pause and pick up where it left off. The scheduler still runs many commands at once by taking turns.
